Status Ledger: Time in Status for Jira

Status Ledger shows how long Jira issues spent in each status, in calendar time or in working hours, and exports the table to CSV. It runs entirely inside Jira Cloud (Forge, Runs on Atlassian): no external server, no data stored outside your site.

Get started

  1. A Jira admin installs Status Ledger from the Atlassian Marketplace.
  2. Open any project and choose Status Ledger in the project sidebar (or Apps → Status Ledger in the top bar for a cross-project report).
  3. The report runs at once for the issues updated in the last 90 days of that project. Change the JQL and press Run report to ask for anything else.

The report

One row per issue, one column per status, in the order the statuses first appear in the issues' history. Each cell is the total time the issue spent in that status, adding up every visit (an issue sent back from Review to In Progress counts both stretches of In Progress). The last row is the average among the issues that entered the status.

  • Issues: up to 100, 250, 500 or 1000 per run. If the query returns more, the report says so.
  • Time: working hours (default) or calendar time (24/7).
  • Show: compact (2d 4h, where a day is one working day in working-hours mode), hours, or days.
  • Cycle time: pick a start status and an end status to add a column with the time from the first entry into the start status to the last entry into the end status (In Progress → Done is the classic cycle time; the first status → Done is lead time).

The report reads issues as you. It only shows issues you can already see in Jira.

Issue panel

On any issue, open the Time in status panel on the right. It lists every status the issue went through with calendar time, working time and the number of visits, and marks the current status.

Working schedule

Open Working schedule in the report to set the working days, the start and end of the day, the time zone (default: your Jira profile time zone) and holidays (YYYY-MM-DD, separated by commas). Daylight saving changes are handled by the time zone. The schedule is saved in your browser and used by the report and the issue panel.

CSV export

Export CSV downloads the table with times in hours (working hours or calendar hours, as shown in the header). Choose semicolon if your Excel uses a comma as the decimal mark (Brazil, most of Europe); the file then uses ; between columns and , for decimals. Copy CSV puts the same text on the clipboard. Cells that start with =, +, - or @ are prefixed with an apostrophe so a spreadsheet never runs them as formulas.

FAQ

Where does the data come from?
From the issue history (changelog) of each issue, read through the Jira REST API when you open the report. Nothing is copied or cached.
Why is the first status of an old issue missing?
If an issue was imported with its history cut, the first recorded change is the start. Time before the first change is counted in the status the change left from.
Does it work with team-managed and company-managed projects?
Yes. Statuses are read by name, so two workflows with a status called "Done" share one column.
Is my data sent anywhere?
No. See the privacy policy.
